# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

RpTv is a free, open-source (MPL-2.0) IPTV player for iPhone and iPad, targeting iOS 26 and the App Store. It ships with no content: users add their own M3U playlist or Xtream Codes account.

## Commands

```sh
Scripts/build-ffmpeg.sh                             # build Packages/FFmpeg/FFmpeg.xcframework from the Vendor/FFmpeg submodule (needed once, before the app builds)
xcodegen generate                                   # regenerate RpTv.xcodeproj after changing project.yml or adding/removing files
swift test --package-path Packages/RpTvKit          # core unit tests on macOS (fast)
swift test --package-path Packages/RpTvKit --filter M3UParserTests   # a single suite
swift test --package-path Packages/FFmpeg            # checks the FFmpeg build (codecs present, LGPL only)
swift test --package-path Packages/StreamBridge      # the FFmpeg player and the AirPlay bridge on synthetic fixtures, HLS server
xcodebuild -project RpTv.xcodeproj -scheme RpTv -destination 'platform=iOS Simulator,name=iPhone 17' build
```
The UI tests (`UITests/`) skip unless `TEST_RUNNER_RPTV_PLAYLIST_URL` points to a served copy of `Support/demo-playlist.m3u`, and (for `GuideUITests`) `TEST_RUNNER_RPTV_GUIDE_PLAYLIST_URL` to the output of `Scripts/make-demo-guide.py`. See README.

## Architecture

- `Packages/RpTvKit` holds all non-UI logic and must keep compiling on macOS so `swift test` works. Don't put UIKit or iOS-only SwiftUI there.
- `App/` holds the SwiftUI app. `AppModel` (@Observable, MainActor) owns the database, sync service, keychain and the on-screen `playerSession` (a `PlayerSession`: coordinator, current channel, zap list). Views read data through `AppDatabase.observe*` async streams (GRDB ValueObservation).
- Storage is GRDB/SQLite (`AppDatabase`). Schema changes go in a **new** migration in `AppDatabase.migrator`. Never edit a shipped migration.
- A sync (`SourceSyncService`) replaces a source's live catalog in one transaction (`replaceLiveCatalog`). `stableKey` identifies channels across resyncs.
- **Credentials never go in SQLite.** Xtream passwords live in the keychain (`CredentialStore`). Xtream stream URLs are built at play time by `PlaybackResolver`.
- **TV guide:** `EPGSyncService` downloads XMLTV to a temp file, inflates gzip (`GzipInflater`), and `AppDatabase.importGuide` streams it (`XMLTVParser`) into `epgChannel`/`programme` in one transaction. Only programmes of guide channels that some channel matches are stored. `channel.guideID` holds the match (`GuideMatcher`: `epgOverride`, then `epgChannelID`, then normalized name). Both the catalog sync and the guide import re-resolve it. It refreshes apart from the catalog sync (12 h staleness by default; both intervals are settings). Rows get now/next from `observeNowNext`, one query per list (`NowNextReader`).
- **Guide grid** (`App/Sources/Features/Guide/`): one 2D `ScrollView` whose `LazyVStack` pins the time ruler as a section header; the channel column is pinned with `visualEffect` offsets, so scrolling never updates state. The timeline spans the whole stored guide (`observeGuideRange`), but slots load only for a window around the viewport (`observeGuide` with `GuideTimeScale.loadWindow`, re-subscribed when the 6-hour bucket changes). Time ↔ x math lives in `GuideTimeScale` (RpTvKit, unit tested). The import keeps past programmes as many days as matched channels' `catchupDays` (max 7, at least 1).
- **Catch-up:** `PlaybackResolver.catchupItem` builds a non-live item. Xtream uses `XtreamCredentials.timeshiftURL` in `source.serverTimeZone` (refreshed every sync). M3U uses `Catchup.m3uURL` with the channel's `catchupMode`/`catchupSource` (Kodi IPTV Simple conventions). `Channel.isCatchupPlayable` decides what's watchable. Reminders are local notifications (`Reminders`); the pending requests are the only record.
- **Movies (VOD):** the `movie` table, swapped with the live catalog in one transaction (`replaceCatalog` with a `SourceCatalog`; `movies: nil` keeps the stored ones, used when an Xtream server fails its VOD calls). M3U entries become movies by `M3UEntry.contentKind` (`/movie/` or `/series/` in the path, or a VOD file extension outside a live group). Xtream details (`get_vod_info`) are fetched when the detail screen opens (`SourceSyncService.refreshDetails`), cached in the row for 7 days, and carried over by `stableKey` on resync. The grid reads `MovieSummary` (a few columns) so saving details doesn't refetch it. `PlayerSession` plays a channel, a movie or an episode (`channel`/`movie`/`episode` optionals).
- **Favorites and recents** (`favorite`, `recentItem`) point at items by `ItemKey` (sourceID, kind, `stableKey`), never by row id, so they survive resyncs. They cover channels, movies and series (`ItemKind`); playing an episode records its series. Recents keep the last 50 plays; an item counts as played after 5 s (`PlayerSession`).
- **Categories:** the user's changes (`isHidden`, `isLocked`, `customName`, `customSortIndex`) live on `mediaCategory` rows and are carried over by `remoteID` when a sync replaces them (`replaceCategories`). Show `displayName`, and order by `customSortIndex` (nulls last), then `sortIndex`. Writes go through `updateCategory`/`renameCategory`/`reorderCategories`, keyed by `remoteID`.
- **Parental controls:** `ParentalControls` (RpTvKit, unit tested) keeps the 4-digit PIN and the Face ID flag in the `CredentialStore`, limits wrong attempts, and holds the session's unlocked state (`isRestricted`). Reads that list channels or movies (category lists, search, favorites, recents, `lastPlayedChannel`) take `includingLocked`, which defaults to `false`; the app passes `AppModel.includesLocked`. `AppModel.authorize` asks for the PIN through the sheet `RootView` shows; the session locks again when the app goes to the background.
- **Settings** (`AppSettings`, UserDefaults) feed `PlaybackResolver.preferences`: the default engine for sources on Automatic, the live buffer, and audio/subtitle languages, which each engine applies (`TrackLanguage` matches track tags).
- **Series:** the `series` table is swapped with the rest of the catalog (`SourceCatalog.series`, `nil` keeps the stored ones). `season` and `episode` point at their series by `seriesKey` (its `stableKey`), not row id. Xtream episodes come from `get_series_info` when the detail screen opens (`SourceSyncService.refreshDetails(of: Series)`), cached for 7 days and kept across resyncs while the series stays in the catalog. M3U episodes come with the playlist (`SeriesCatalog.includesEpisodes`): `M3UEntry.contentKind` is `.episode` when the name parses as one (`EpisodeName`: "Show S01E02", "Show 1x02"), grouped into series by show name within their group. Movies and Series share the Library tab (`LibraryView`), which keeps the iPhone tab bar to five.
- **Watch progress** (`playbackProgress`) is keyed by `ItemKey` (kind `.movie` or `.episode`), so it survives resyncs. `PlayerSession` saves it every 10 s while playing, on pause, on leaving the app and on close; 95 % or more counts as watched (`PlaybackProgress`). Resuming passes `PlaybackItem.startPosition`. Continue Watching (`observeContinueWatchingMovies`/`Episodes`) shows unfinished items, one episode per series. Up Next (`UpNextPrompt`) appears 30 s before an episode ends and plays the next after a 10 s countdown.
- **Search** uses external-content FTS5 tables (`channelSearch`, `movieSearch`, `seriesSearch`, `programmeSearch`, `unicode61` with diacritics removed) queried with `FTS5Pattern(matchingAllPrefixesIn:)`. They have **no sync triggers** (triggers made 100k-channel resyncs ~7× slower): any write that adds, removes or renames channels, movies, series or programmes must call `AppDatabase.rebuildSearchIndex` in the same transaction, as `replaceCatalog`, `importGuide` and `deleteSource` do.
- Xtream JSON is inconsistent between servers. Decode with the `lossy*` helpers in `Support/LossyDecoding.swift`.
- Playback goes through the `PlayerEngine` protocol. `PlaybackCoordinator` (in RpTvKit) picks the first engine (the source's `enginePreference`, then the engine that last worked for that item, then `EngineSelector` on the URL). It switches from AVPlayer to the FFmpeg player (`.ffmpeg`) when AVPlayer fails, or when a live stream hasn't started after 10 s. `PlayerScreen` renders whichever engine is active. `EnginePreference` and `PlayerEngineKind` still read `"vlc"` (saved before VLCKit was dropped) as `.ffmpeg`.
- **FFmpeg player:** `StreamPlayer` (`Packages/StreamBridge/Sources/StreamBridge/Player/`) demuxes and decodes with FFmpeg and renders through an `AVSampleBufferDisplayLayer` and an `AVSampleBufferAudioRenderer` on one `AVSampleBufferRenderSynchronizer`. `PlaybackPipeline` runs three threads (read, video, audio) linked by `PacketQueue`s; a seek bumps a serial that tells decoders to flush. `StreamPlayer` owns the clock: it starts it once enough is read (`PlayerSource.buffer`) and stops it when the stream runs dry. Video decodes with VideoToolbox where it can (`VideoDecoder`); `VideoConverter` deinterlaces with `bwdif` and scales non-square pixels to square on the GPU. Live timestamps go through `LiveTimeline`, which smooths over discontinuities, and `LiveRateController` plays live streams at 0.98× or 1.02× (user speed is ignored for live) to keep the buffer near its target when the server's clock drifts. Subtitles (text and bitmap, not teletext) are decoded on the read thread into cues that `SubtitleOverlay` draws. CEA-608 closed captions are read from each video frame's `AV_FRAME_DATA_A53_CC` on the video thread (FFmpeg's `eia_608` decoder in `real_time` mode); they become subtitle track `PlaybackPipeline.captionTrackID` once the first caption is decoded. `FFmpegPlayerEngine` (app target) wraps it as a `PlayerEngine`, with Picture in Picture on the display layer, and stops decoding video in the background without PiP. Tests play the fixtures through the real renderers.
- FFmpeg is built **from source**: the `Vendor/FFmpeg` git submodule (pinned to a release tag) is compiled by `Scripts/build-ffmpeg.sh` into a dynamic `FFmpeg.xcframework` (iOS, simulator, macOS) inside `Packages/FFmpeg`, which StreamBridge links (the app gets it through StreamBridge). LGPL components only: never add `--enable-gpl` or `--enable-nonfree`. Keep it out of RpTvKit. When moving the submodule to a new tag, update the tag in `THIRD_PARTY_NOTICES.md`.
- **AirPlay bridge** (`Packages/StreamBridge`): the FFmpeg player decodes on the device, so AirPlay only gets its sound. While AirPlay is on, `PlaybackCoordinator.prefersBridge` swaps `.ffmpeg` for `.bridge`: `BridgedPlayerEngine` (app target) runs `HLSBridge` (FFmpeg demux; copy H.264/HEVC/AAC/AC-3; re-encode other audio to AAC with AudioToolbox and other video to H.264 with VideoToolbox, deinterlacing with `bwdif`), serves the HLS with `HLSServer` on the Wi-Fi address, and plays it in an `AVPlayerEngine`, which AirPlay can hand to the TV. What to copy or re-encode is decided in `BridgePlan`.
- StreamBridge is a dynamic library (`type: .dynamic`, embedded in `project.yml`). Never call FFmpeg from the app target directly: go through StreamBridge.

## Conventions

- Swift 6 with strict concurrency. Swift Testing (`@Test`) for unit tests, with fixtures in `Tests/RpTvKitTests/Fixtures`.
- Every source file starts with the MPL-2.0 header.
- Never add real channel lists or provider URLs anywhere in the repo.
